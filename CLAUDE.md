# Project Rules

## Communication
- Respond in Ukrainian. Use English for technical terms (class names, method names, etc.)
- Keep responses short and concise
- No trailing summaries ("what we did today", "next steps") unless asked

## Showing code
- Every code snippet MUST start with the full file path as a header, e.g.:
  `src/frontend/FinanceManagement.Web/Services/Operations/OperationQuery.cs`
- After the path — one line describing what to do (add field, replace line X, add using, etc.)
- Add inline comments in code snippets to explain what each part does
- Add short explanation after code blocks

## When Claude writes code directly into files
- No inline comments
- No XML doc comments

## Workflow
- Propose changes first → wait for confirmation → then show code or edit
- "перевірь" = verify and report only, do NOT auto-fix
- Do NOT create, copy or edit files without explicit user confirmation ("ок")
- Do NOT commit unless explicitly asked
- No Co-Authored-By in commit messages

## After new concepts
- Proactively ask if user wants to add the concept to interview notes
